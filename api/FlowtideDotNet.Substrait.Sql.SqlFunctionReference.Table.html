Remarks

Names and examples use Flowtide SQL. Square brackets in signatures mark optional arguments; they are not literal SQL. Extension signatures, type declarations and required options describe Substrait bindings, not additional SQL arguments. The Flowtide notes and constraints apply to each listed profile. Aggregate, window and table functions are separate capabilities.

hopping_window(timestamp, hop_amount, hop_unit, size_amount, size_unit)

Emit every fixed-size window containing a timestamp, with starts spaced by the hop duration. A smaller hop than size creates overlapping windows; equal durations produce one tumbling window; a larger hop can leave gaps and emit no rows. Results are emitted from the latest matching start backwards, though a SQL result requires ORDER BY to guarantee presentation order. The number of matching windows varies by alignment and is at most ceil(size_ticks / hop_ticks). The compile-time guard rejects floor(size_ticks / hop_ticks) > 100000; a non-integral ratio just below 100001 can therefore emit 100001 rows. Duration amounts must be positive integer numeric literals; units must be string literals WEEK, DAY, HOUR, MINUTE, SECOND, MILLISECOND or MICROSECOND (case-insensitive). Fractions, column/expression durations, MONTH and YEAR are rejected. Each converted duration must fit Int64 ticks. Days are fixed 24-hour durations and weeks are seven days. Window starts align to UTC ticks from 0001-01-01T00:00:00Z; a week grid therefore begins Monday UTC, not local calendar midnight. Results preserve the input timestamp offset. Boundaries are start-inclusive and end-exclusive. Null/non-timestamp input emits no rows.

  • Extension signatures: hopping_window:ptstz_i64_str_i64_str
  • Extension source: extension:io.github.koralium.flowtide:functions_datetime
  • Extension type declaration: (precision_timestamp_tz<7>, i64 (constant), string (constant), i64 (constant), string (constant)) -> rows(window_start: precision_timestamp_tz<7>, window_end: precision_timestamp_tz<7>)
  • Duration units: [WEEK, DAY, HOUR, MINUTE, SECOND, MILLISECOND, MICROSECOND]
  • Fanout guard: floor(size_ticks / hop_ticks) <= 100000
  • Literal arguments: [1, 2, 3, 4]
  • Output column count: 2
  • Timestamp precision: 7
SELECT o.id, window_start, window_end FROM orders o INNER JOIN hopping_window(o.order_time, 5, 'MINUTE', 10, 'MINUTE')
SELECT o.id, window_start FROM orders o LEFT JOIN hopping_window(o.order_time, 10, 'MINUTE', 5, 'MINUTE')

tumbling_window(timestamp, size_amount, size_unit)

Emit the single fixed-size window containing a timestamp. Duration amounts must be positive integer numeric literals; units must be string literals WEEK, DAY, HOUR, MINUTE, SECOND, MILLISECOND or MICROSECOND (case-insensitive). Fractions, column/expression durations, MONTH and YEAR are rejected. Each converted duration must fit Int64 ticks. Days are fixed 24-hour durations and weeks are seven days. Window starts align to UTC ticks from 0001-01-01T00:00:00Z; a week grid therefore begins Monday UTC, not local calendar midnight. Results preserve the input timestamp offset. Boundaries are start-inclusive and end-exclusive. Null/non-timestamp input emits no rows.

  • Extension signatures: tumbling_window:ptstz_i64_str
  • Extension source: extension:io.github.koralium.flowtide:functions_datetime
  • Extension type declaration: (precision_timestamp_tz<7>, i64 (constant), string (constant)) -> rows(window_start: precision_timestamp_tz<7>, window_end: precision_timestamp_tz<7>)
  • Duration units: [WEEK, DAY, HOUR, MINUTE, SECOND, MILLISECOND, MICROSECOND]
  • Literal arguments: [1, 2]
  • Output column count: 2
  • Timestamp precision: 7

SELECT window_start, COUNT(*) FROM orders o INNER JOIN tumbling_window(o.order_time, 10, 'MINUTE') GROUP BY window_start

unnest(collection)

Emit one column and one row per list element or map entry. List elements retain their original value kind, including null elements. For a map, each result is a single map/object with string fields key and value containing the original key and value; these are not separate columns. Null, empty, and non-list/non-map inputs emit no rows. SQL uses the table alias as the single output column name, or generates a name when no alias is supplied. No ordinality column is added.

  • Extension signatures: unnest:list, unnest:map
  • Extension source: extension:io.github.koralium.flowtide:functions_table_generic
  • Extension type declaration: (list<any1>) -> rows(value: any1)
  • Extension type declaration: (map<any1,any2>) -> rows(value: map<string,any>)
  • Output column count: 1
SELECT val FROM UNNEST(list(1, 2, 3)) val
SELECT d.id, element FROM documents d LEFT JOIN UNNEST(d.items) element
SELECT d.id, element FROM documents d INNER JOIN UNNEST(d.items) element ON element = 123
