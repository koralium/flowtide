AddFlowtideStream(IServiceCollection, string)

Registers a named stream that continuously maintains query results as source data changes. Use the returned builder to configure its plan, source and sink connectors, and state storage.

public static IFlowtideDIBuilder AddFlowtideStream(this IServiceCollection services, string name)

Parameters

services IServiceCollection

The application service collection.

name string

A stable stream name used to identify its services and persisted state.

Returns

IFlowtideDIBuilder

A builder for configuring the plan, connectors and state storage.

Examples

A complete console application using the .NET Generic Host. Install the FlowtideDotNet.DependencyInjection and Microsoft.Extensions.Hosting NuGet packages. This example uses a built-in VALUES source and the console sink, so no external database is needed. 

using System.IO;
using FlowtideDotNet.Core.Sinks;
using FlowtideDotNet.DependencyInjection;
using Microsoft.Extensions.DependencyInjection;
using Microsoft.Extensions.Hosting;

var builder = Host.CreateApplicationBuilder(args);

builder.Services.AddFlowtideStream("hello")
    .AddSqlTextAsPlan("""
        INSERT INTO console
        SELECT id, upper(name) AS name
        FROM (VALUES (1, 'Ada'), (2, 'Linus')) AS people(id, name);
        """)
    .AddConnectors(connectors => connectors.AddConsoleSink("console"))
    .AddStorage(storage =>
    {
        storage.AddTemporaryStorage(Path.Combine(Path.GetTempPath(), "flowtide-hello"));
    });

using var host = builder.Build();
await host.RunAsync();

Run the application to start the stream and print its results. The host handles startup and shutdown; press Ctrl+C to stop. Temporary storage is cleaned up on disposal. For state that survives restarts, replace the storage call with storage.AddFileStorage("./state/hello") and keep that directory.

Remarks

A stream needs a plan, source and sink connectors, and state storage. Configure these on the returned builder before starting the application host:

  1. Plan Use AddSqlTextAsPlan(IFlowtideDIBuilder, string) for inline SQL, AddSqlFileAsPlan(IFlowtideDIBuilder, string) for a SQL file, or AddSqlPlan(IFlowtideDIBuilder, Action<SqlPlanBuilder>) to configure a SQL plan builder. The query describes the result to maintain; INSERT INTO names its destination.
  2. Source and sink connectors Use AddConnectors(Action<IDependencyInjectionConnectorManager>) to register sources for the input tables and sinks for the destinations named in the plan. Install the connector packages for your data systems and make sure their table names match the SQL. Built-in inputs such as VALUES need no source connector.
  3. State storage Use AddStorage(Action<IFlowtideStorageBuilder>) to store operator state, source positions and checkpoints. Choose AddTemporaryStorage(IFlowtideStorageBuilder, string?) for development and tests, or AddFileStorage(IFlowtideStorageBuilder, string) for local state that survives application restarts.

The application host starts and stops the stream. Calling this method registers its services; run the host after completing the configuration, as shown in the example. Give independent streams their own names and storage directories. Calling this method again with the same name on the same service collection returns the existing builder.
