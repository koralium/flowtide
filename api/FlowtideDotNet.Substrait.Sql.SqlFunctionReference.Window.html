Remarks

Names and examples use Flowtide SQL. Square brackets in signatures mark optional arguments; they are not literal SQL. Extension signatures, type declarations and required options describe Substrait bindings, not additional SQL arguments. The Flowtide notes and constraints apply to each listed profile. Aggregate, window and table functions are separate capabilities.

avg(x) OVER (...)

Profile: fp64

Null input values are ignored; empty/all-null frames return null. Without ORDER BY, SQL uses the whole partition. With ORDER BY and no explicit frame, SQL uses ROWS UNBOUNDED PRECEDING through CURRENT ROW, including only rows through this physical row rather than all equal-order peers. Explicit ROWS bounds support preceding/following/current/unbounded endpoints. RANGE, GROUPS and dynamic frame-bound expressions are not implemented. Uses the aggregate definition as a window function.

  • Frame bounds: [UNBOUNDED_PRECEDING, PRECEDING, CURRENT_ROW, FOLLOWING, UNBOUNDED_FOLLOWING]

lag(x [, offset [, default]]) OVER (...)

Return x from a preceding row in the same partition, defaulting to offset 1. Negative offsets reverse direction and zero selects the current row. A missing target yields the provided default, evaluated on the current row, or null when omitted. Null target values are respected. SQL requires ORDER BY and rejects ROWS frames; IGNORE NULLS is not implemented. These upstream signatures apply when any explicit offset is non-null and fits Int32, and the default has the same type as x. A null offset has different native behavior, described below.

  • Extension signatures: lag:any, lag:any_i32, lag:any_i32_any
  • Extension source: extension:io.substrait:functions_arithmetic
  • Extension type declaration: (any1) -> any1?; nullability=DECLARED_OUTPUT
  • Extension type declaration: (any1, i32) -> any1?; nullability=DECLARED_OUTPUT
  • Extension type declaration: (any1, i32, any1) -> any1?; nullability=DECLARED_OUTPUT
  • Default same type as value: true
  • Explicit offset must be non null: true
  • Frame types: []
  • Plan representation: CONSISTENT_PARTITION_WINDOW
  • Requires order by: true
  • Sql distinct: false
  • Supports filter: false

session_window(gap_amount, gap_unit) OVER (... ORDER BY timestamp ASC)

Return the start timestamp of the session containing each row. Exactly one ascending timestamp sort expression is required. A neighbouring gap equal to the limit remains in the session; a larger gap starts a new one. Null/non-timestamp sort values return null and do not split the run. Inserts can merge sessions and deletes can split them. The gap is a positive integer literal and a string unit literal; WEEK/DAY are fixed durations, not calendar arithmetic. Explicit frames are rejected. This binding is registered only for the bulk window operator.

  • Extension signatures: session_window:i64_str
  • Extension source: extension:io.github.koralium.flowtide:functions_datetime
  • Extension type declaration: (i64 (constant), string (constant)) -> precision_timestamp_tz?<7>; nullability=DECLARED_OUTPUT
  • Frame types: []
  • Gap units: [WEEK, DAY, HOUR, MINUTE, SECOND, MILLISECOND, MICROSECOND]
  • Literal arguments: [0, 1]
  • Order by count: 1
  • Order by direction: ASC
  • Order by type: precision_timestamp_tz<7>
  • Plan representation: CONSISTENT_PARTITION_WINDOW
  • Requires bulk window operator: true
  • Requires order by: true
  • Sql distinct: false
  • Supports filter: false
  • Timestamp precision: 7
SELECT session_window(30, 'MINUTE') OVER (PARTITION BY user_id ORDER BY event_time) FROM events

surrogate_key_int64() OVER (...)

One stateful counter key per partition, shared by all its rows. Without PARTITION BY, all rows share one key. ORDER BY is optional; SQL rejects ROWS frames. Live partitions retain their key across updates and checkpoint restore; deleting and recreating a partition can assign a new key. Allocation is operator-scoped and not deterministic across a full replay.

  • Extension signatures: surrogate_key_int64:
  • Extension source: extension:io.github.koralium.flowtide:functions_aggregate_generic
  • Extension type declaration: () -> i64; nullability=DECLARED_OUTPUT
  • Deterministic: false
  • Frame types: []
  • Plan representation: CONSISTENT_PARTITION_WINDOW
  • Requires order by: false
  • Sql distinct: false
  • Supports filter: false
SELECT surrogate_key_int64() OVER (PARTITION BY p) FROM t
